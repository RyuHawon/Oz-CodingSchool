
## 트랜잭션[ACID]
### GearWiki에서 유저가 장비를 교체하는 작업은 데이터의 일관성을 위해 반드시 하나의 트랜잭션 단위로 처리되어야 합니다.

원자성 (Atomicity): 장비 교체 시 '기존 장비 해제'와 '새 장비 장착'은 모두 성공하거나, 하나라도 실패하면 모두 Rollback 처리 되어야 합니다.

일관성 (Consistency): 트랜잭션 완료 후에도 모든 데이터는 정의된 규칙을 만족해야 합니다. (예: 캐릭터의 총 공격력 합산 방식은 항상 동일한 로직을 유지해야 함)

고립성 (Isolation): 여러 유저가 동시에 장비창을 수정하더라도, 각 트랜잭션은 서로 간섭할 수 없습니다. 한 유저가 아이템을 장착하는 동안 다른 프로세스가 그 중간 상태를 읽을 수 없습니다. (격리 수준 보장)

지속성 (Durability): 장비 장착이 완료되었다는 메시지를 받았다면, 이후 시스템 장애가 발생하더라도 해당 데이터는 DB에 영구적으로 보존되어야 합니다.

## 데이터 무결성 (Integrity)

엔티티 무결성 (Entity Integrity): 각 테이블의 ID칼럼은 PK, AI, NN

참조 무결성 (Referential Integrity): User_Inventory에 등록되는 item_id는 반드시 Items에 존재하는 아이템이어야 합니다. 외래키(FK) 제약 조건을 통해 아이템 테이블에 존재하는 아이템만 보유할 수 있게 제한.

도메인 무결성 (Domain Integrity): 아이템의 스탯 수치는 반드시 INT형 데이터여야 하며, 장비 카테고리는 지정된 범위(무기, 방어구, 악세서리 등) 내의 값만 가질 수 있도록 제한합니다.

사용자 정의 무결성 (User-defined Integrity): 특정 장비는 '레벨 n 이상만 착용 가능' CHECK, Trigger 조건을 이용해 무결성 유지

## 동시성 제어 (Concurrency Control)
### 다수의 사용자가 동시에 데이터를 조회하거나 수정할 때 발생하는 문제를 관리합니다.

-읽기를 위해-
MVCC (Multi-Version Concurrency Control): MySQL(InnoDB)에서 주로 사용하는 방식으로, 관리자가 아이템 스탯을 수정 중이더라도 사용자는 수정 전의 '스냅샷' 데이터를 읽을 수 있게 합니다.

-쓰기를 위해-
행 단위 잠금 (Row-level Lock): 한 유저가 여러 기기에서 동시에 접속하여 장착 정보를 변경할 때 데이터가 꼬일 수 있습니다. 특정 유저의 User_Equipment 데이터를 수정할 때는 해당 행(Row)에만 배타적 락(Exclusive Lock)을 걸어 데이터의 정확성을 보장합니다.

데드록 감지 (Deadlock Detection): MySQL InnoDB의 기본 기능을 활용, 다중 접속 환경에서 유저가 인벤토리 조회/수정과 장비 장착을 동시에 수행할 경우 등 예상하지 못한 무한 대기 상태를 방지하기 위해 시스템 차원의 데드록 감지 로직을 활성화

MySQL 선택 이유

1. 정형/비정형 데이터 관리 (Structured Data)
GearWiki에서 관리하는 아이템 정보와 유저 데이터는 그 구조가 매우 명확하고 고정적인 정형 데이터입니다.
아이템 위키의 특성상 각 항목의 속성이 일정해야 하며, 테이블 간의 엄격한 관계를 통해 데이터의 일관성을 유지하기에 ACID 트랜잭션과 JOIN이 가능한 RDBMS(관계형 데이터베이스) MySQL이 가장 적합합니다.

2. 확장성 (Scalability)
위키 서비스는 데이터 수정보다 다수 사용자의 읽기(조회) 요청이 훨씬 많습니다.
MySQL은 관계형 데이터베이스지만 Read Replica(읽기 전용 복제본) 구성을 통해 조회 성능을 수평적으로 확장할 수 있어, 사용자 증가에 유연하게 대응할 수 있습니다.

3. 응답 속도 (Response Speed)
인덱스(Index) 기반의 빠른 데이터 검색 성능을 제공합니다.
아이템의 수는 점점 늘어날것이므로 향후 아이템 데이터가 수천개가 되더라도 특정 카테고리나 하위 타입을 필터링할 때, B-Tree 인덱스를 활용하여 매우 빠른 응답 속도를 보장합니다.

4. 트랜잭션 처리 (Transaction Processing)
InnoDB 엔진을 통한 강력한 ACID 보장.
유저가 장비를 교체할 때 해제와 장착이 동시에 일어나야 하는 원자성(Atomicity)이 필수적입니다.
MySQL은 데이터의 유실이나 오류 없이 안전한 처리를 지원하므로 유저의 장비 보유,장착관리 시스템에 적합합니다.

5. 실시간 처리 가능 여부 (Real-time Processing)
낮은 지연 시간(Low Latency)의 즉각적인 쿼리 결과 반환.
유저가 장비를 착용하자마자 최종 합산 능력치(공격력, 이동속도 등)가 즉시 반영되어야 합니다.
MySQL의 최적화된 쿼리 실행 엔진은 복잡한 JOIN과 집계 연산을 실시간에 가깝게 처리할 수 있습니다.

6. 웹 서비스의 표준 및 안정성
GearWiki는 웹 서비스인만큼 가장 많이 쓰이는, 웹 서비스 설계의 표준을 따르기 좋은 MySQL이 적합합니다.
