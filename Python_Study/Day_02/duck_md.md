# [Design Pattern] Strategy Pattern (전략 패턴)

## 1. 개요 및 핵심 원칙
전략 패턴은 알고리즘군을 정의하고 각각을 캡슐화하여 교체해서 사용할 수 있게 만드는 패턴입니다. 실행 중에 알고리즘을 선택할 수 있게 하여 유연성을 극대화합니다.

* **변하는 부분의 분리**: 달라지는 행동(비행, 소리)을 찾아내서 별도의 클래스 집합으로 분리합니다.
* **구성(Composition) 사용**: "오리는 ~이다(is-a)"보다 "오리는 ~을 갖는다(has-a)"는 관계를 이용합니다.
* **인터페이스 의존**: 구체적인 구현 클래스가 아닌 추상화된 인터페이스에 의존하여 코드를 짭니다.



## 2. SimUDuck 실행 로직 상세 분석
작성된 `rubber_duck` 인스턴스의 생성부터 실행까지의 내부 동작 과정입니다.

### 1) 인스턴스 초기화 및 조립 (Initialization)
* **상속 및 생성자 실행**: `rubber_duck` 생성 시 `super().__init__()`을 호출하여 부모인 `duck` 클래스의 `__init__`을 실행합니다. 이 과정에서 `fly_behavior`와 `quack_behavior`라는 변수 주머니(None 상태)가 생성됩니다.
* **부품 장착**: `self.set_fly(fly_not())` 메서드를 실행합니다. 이때 `self`는 `rubber_duck` 자신을 가리키며, 부모로부터 물려받은 `set_fly` 메서드를 통해 자신의 `fly_behavior` 변수에 `fly_not` 객체를 할당합니다.
* **소리 부품 장착**: 동일한 방식으로 `quack_behavior`에 `quack_quiet` 객체를 넣어 초기 조립을 마칩니다.

### 2) 행동 위임 및 실행 (Delegation)
* **메서드 호출**: `first_duck.perform_fly()`를 호출하면, 오리 객체는 직접 비행 로직을 처리하지 않습니다.
* **위임**: 내부적으로 `self.fly_behavior.fly()`를 실행하여, 미리 장착된 `fly_not` 객체에게 실제 작업을 넘깁니다.
* **결과**: `fly_not` 클래스의 `fly` 메서드에 정의된 `print("I can't fly")`가 최종적으로 출력됩니다.



## 3. 결론 및 장점
* **유연성**: `set_fly()`와 같은 세터 메서드를 통해 실행 중에 오리의 행동을 즉시 바꿀 수 있습니다.
* **재사용성**: 한 번 만든 비행 전략(`fly_high` 등)을 여러 종류의 오리 클래스에서 중복 코드 없이 공유할 수 있습니다.
* **독립성**: 새로운 비행 방식이 추가되어도 기존의 `duck` 클래스나 다른 오리 클래스를 수정할 필요가 없어 유지보수가 용이합니다.
